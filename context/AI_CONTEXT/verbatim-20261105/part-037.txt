### 2. Local Work / 按钮可用性
- `Local Work` 的行为固定为：
  - 如果检测到本地 ACP bridge，则默认走本地 ACP。
  - 如果未检测到 bridge，不允许伪装成可用；Home 上显示 `degraded`，Launch 按钮禁用或降为明确提示。
- ACP bridge 探测规则固定为：
  - 优先 `LONGCLAW_LOCAL_ACP_SCRIPT`
  - 否则回退到当前兼容脚本路径
  - 结果暴露到 renderer，作为 `Local Work` 的 readiness 来源
- `Reset runtime`、`Dispatch via WeClaw`、`Pack shortcuts`、`detail drawer actions` 全部要加 availability guard：
  - 不满足前置条件时，不执行调用
  - 给出明确的 inline notice，而不是抛异常到全局 error banner
- `WeClaw Dispatch` 这轮只修“按钮/入口稳定性”和状态表达，不要求补完整真实微信闭环。

## Summary
- Longclaw 需要从“单轴三模式”改成 **双层建模**：
  - `产品级 work_mode`
  - `部署级 runtime_profile`
- 这能同时满足两件事：
  - 保留你要的三种用户体验
  - 不把你当前机器上的 `WeClaw -> 本机 ACP 常驻桥接` 误写成产品默认形态
- phase 1 的统一规则固定为：
  - **模型层统一云端**
  - `local` = 本地环境 + 云端模型
  - `cloud_sandbox` = 云端环境 + 云端模型
  - `weclaw_dispatch` = 微信/WeClaw 控制本地环境 + 云端模型
- 你当前机器只是一种 `runtime_profile`：
  - `dev_local_acp_bridge`
